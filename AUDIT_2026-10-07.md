# Repository review and fixes — 7 October 2026

Reviewed the Python runtime, API boundaries, account lifecycle, purpose leases,
coding tools, model transports, offline bundle verification, encrypted retention,
receipt generation/verification, backups/recovery, launchers, CLI guidance and
tests. User operational data was excluded; tests use isolated synthetic storage.

## Practical limits

Real LLM/VLM/diffusion quality, Linux/gVisor execution, native POSIX deployment,
server-side retention and OS network isolation were not established by these
tests. Model calls in the regression suite use deterministic adapters or local
fixture servers. Process/listener checks measure local identity; assertions about
loaded weights and network isolation require a separately provisioned independent
attestor. The release remains software assurance, with a fifteen-minute review
ceiling, rather than hardware attestation.

Receipt commitments are suitable for maintaining a separate offline audit anchor;
writing an export does not establish such an anchor. The receipt ledger is
verified in full during protected operations, and bundle custody revalidates
declared file contents. Large ledgers or model bundles therefore carry an I/O and
verification cost that should be measured on the intended deployment hardware.

New self-hashed demo receipts verify portably. Existing demo receipts produced by
the earlier simulated TPM formula are preserved and will continue to fail hash
verification; this review did not rewrite historical evidence.
