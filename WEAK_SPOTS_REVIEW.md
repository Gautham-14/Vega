All seven actionable findings from the 10 October 2026 folder review have been fixed in source and covered by regression tests.

| Finding | Implemented fix |
| --- | --- |
| Quadratic scanner work | Linear token/state and comment scans; API text limited to 65,536 characters and internal scans to 1,000,000. Hidden-character examples and rule matches are bounded. |
| Serial VM incident controls | Bounded threaded HTTP gateway and concurrent guest forwarding; response IDs correlate the existing authenticated channel. Eight ordinary operations and four incident operations have separate slots. A five-second absolute header/body deadline stops trickling clients. |
| Incorrect RPC response deadline | Response framing receives the caller's absolute deadline instead of creating a new five-second deadline. Server inbound frames retain their short deadline. |
| Shared native incident capacity | Authenticated, role-checked incident requests use four reserved leases, two per actor, and two reserved upload readers with a 16 KiB cap. Privileged MFA step-up also has reserved capacity. Route authorization remains enforced. |
| Unbounded scanner metadata | API identifiers are limited to 120 safe ASCII characters. Internal unsafe references become SHA-256 digests. Scanner and control events share bounded persistence and 4,000-row retention without raw payloads. |
| Expired objects consuming quotas | Schema 3 adds signed archival tombstones. Supported expiry archival verifies seals, preserves running work and retained content, and commits receipt commitments before removing inactive rows. Tombstones prevent API identity reuse; revocations and receipt history remain. |
| Repeated full-ledger verification | A process-local verified checkpoint avoids historical rescans across normal appends and lockdown checks. Ledger writes, external commits, database replacement and connection reopening invalidate it. Head signatures and the independent witness remain checked; explicit audits, startup and recovery perform full verification. |

Relevant implementation: [scanner rules](aegis/security/rules.py), [event storage](aegis/storage/events.py), [incident admission](aegis/security/incident.py), [RPC framing](aegis/security/local_rpc.py), [VM host](aegis/vm/host.py), [VM guest](aegis/vm/guest.py), [expiry archival](aegis/control/maintenance.py), and [receipt checkpoints](aegis/control/store.py).

The shared SQLite connection is serialized under the storage lock. Context-bound handles become unusable when their context exits; nested helpers use savepoints and cannot commit an outer rollback. Setup failures close the connection, and shutdown/offline administration releases it. Newly measured coding and media implementations include the new storage and security gates, so existing approvals require fresh measurement after an upgrade.

Use `aegis maintenance status` for quota counts and the 75% high-water warning. Use `aegis maintenance archive` as a Security Officer or Key Custodian for expiry archival. The authenticated API equivalents are `GET /api/security/quotas` and `POST /api/security/maintenance`. Periodic maintenance and admission at the per-kind ceiling also attempt archival. The allowed signed operational kinds are approvals, purpose/coding/advisory leases, coding/advisory tasks, media jobs and coding export references. Permanent policy, account, revocation and unsigned legacy records are retained; quota and disk limits still apply to those records. Archival reduces active counts, not the immutable audit ledger. Back up and stop services before upgrading an existing database; no existing user database was migrated during this work.
